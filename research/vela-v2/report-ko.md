## 1. 결론: 1860 목표 통과, 1880은 미달

새로운 고정 정책의 독립 **100,000게임** 평균 최종 score는 **1863.96061점**이다. 표본 표준편차는 202.88904, 표준오차는 0.64159이며, 정규근사 양측 95% 신뢰구간은 **[1862.70309, 1865.21813]**이다.

평균 점추정뿐 아니라 95% 신뢰구간 하한도 1860을 넘었으므로, 이번 연구에서 사전 기록한 보수적 기준으로 **1차 목표를 통과**했다. 1880까지는 점추정 기준 **16.03939점** 남았다. 도전 목표와 전역 최적성은 달성했다고 주장하지 않는다. 통계적 통과는 모든 게임에서 1860 이상을 얻는다는 뜻도, 실제 기대값에 관한 수학적 증명도 아니다.

같은 새로운 시드 100,000개에서 기존 v1도 다시 실행했다.

## 2. 이번에 실제로 변경한 부분

선정 정책은 새 대형 신경망이 아니다. v1의 약 160MB 원시 가치표와 실제 게임의 두 단계 기대값 탐색을 유지하고, **남은 덱의 장기 가치 잔차**를 더했다. 손패 보존 가중치는 0.95에서 0.975로 바꾸었다. 쌍 상호작용 계수 0.75와 계획 창 24는 유지했다.

빈 손패 가치 B, 단일 카드 추가 가치 U, 두 카드의 비가산 상호작용 Δ를 사용하면 최종 근사는 다음과 같다.

```
V_hat(s) = B(s)
         + 0.975 * sum U(c)
         + 0.73125 * sum Delta(c,d)
         + D_hat(deck,r,bonus)
```

0.73125는 0.975 × 0.75이다. 원본 게임의 이동, 이벤트, 드로우, 더블, 종료 조건은 변경하지 않았다.

### 2.1 남은 덱의 잔차

카드 효과 c의 기준 가치는 기존 모델의 지평 24·보너스 없음 상태에서 위치 100~2299의 단일 카드 추가 가치를 평균하여 계산했다. 전체 30개 ID의 효과별 빈도로 평균을 뺀 중심화 값이 `deckCard[c]`다. 따라서 덱에 강한 카드가 상대적으로 많이 남았는지, 이미 빠졌는지가 잔차에 반영된다. 이는 현재 덱을 항상 전체 덱과 동일하게 취급하던 근사를 보정하기 위한 특징이다.

남은 덱을 D, 그 크기를 m, 내부 계획의 잔여 유료 주사위를 r, 보너스 여부를 b라고 두면 다음 식을 사용했다.

```
z(D) = sum_(id in D) deckCard[class(id)]
D_hat(D,r,b) = 0.6 * min(1, 0.7*(r+b)/m) * z(D)
```

0.7은 미래 드로우 수를 근사하는 계수이고 0.6은 보정 강도다. 이 식은 학습·검증된 정책의 휴리스틱 구성요소이며, 실제 남은 덱의 정확한 장기 최적값은 아니다. 위치·손패·덱을 함께 조건으로 하는 고차 상호작용을 모두 모델링하지도 않는다.

드로우 전의 z가 주어졌을 때, m>1이면 다음 덱의 z 기대값은 `(m-1)/m * z`이다. m=1이면 전체 덱으로 재생성되므로 중심화된 잔차는 0이다. 따라서 드로우 뒤에 덱이 그대로 남아 있는 것처럼 보정하지 않았다. 종료 상태의 잔차는 0이다.

실제 남은 횟수가 24보다 크면 내부 탐색 창을 24로 둔다. 실제 100회 잔여량을 그대로 덱 보정 계수에 넣는 별도 실험도 했지만, 최종 정책에는 넣지 않았다.

### 2.2 실제 선택과 정보 사용

첫 두 행동에서는 실제 남은 덱과 손패, 주사위 합·더블의 결합확률, 착지, 종료 조건을 사용한다. 첫 행동의 결과를 관측한 뒤 두 번째 행동을 선택할 수 있도록 기대값을 계산한다. 그 이후는 위 근사 가치로 평가한다.

정책은 현재 상태만 읽는다. 환경 RNG, 초기 시드, 미래 주사위 또는 미래 드로우를 읽지 않는다. 현재 상태의 `deckMask` 관측이 가능하다는 조건은 v1과 같다.

## 3. 후보 선택과 개발 실험

개발 은행과 최종 은행은 분리했다. 최종 후보의 계수는 새 최종 게임을 읽기 전에 고정했다. 다음 수치들은 후보 선택용이며 최종 성능과 혼동하면 안 된다.

### 3.1 덱 보정과 가중치

동일한 개발 시드 2709101000에서 각각 10,000게임을 실행했다.

| 덱 강도 | 손패 가중치 | 평균 score |
|---:|---:|---:|
| 0 | 0.95 | 1857.7414 |
| 0.6 | 0.95 | 1861.7012 |
| 0.6 | 1.0 | 1862.2425 |
| **0.6** | **0.975** | **1864.8335** |

다른 5,000게임 개발 은행에서는 보정 강도 0.3, 0.6, 1.0도 비교했다. 강도 0.6·가중치 0.95가 1865.5770, 강도 1.0은 1859.9656이었다. 보정을 강하게 하는 것 자체가 개선을 보장하지 않았다.

일부 2,000게임 탐색은 주사위·드로우 PRNG를 분리한 공통 난수 비교도 사용했다. 파일명 `crn-*` 및 일부 `next-*` 결과가 이에 해당한다. 이를 최종 canonical 단일-stream 평가와 섞어 집계하지 않았다. 분리 PRNG가 차이의 분산을 크게 줄였다는 결론도 내리지 않는다.

### 3.2 더 깊은 탐색

기존 가치 근사를 유지한 채 3단계 탐색을 추가했다. 종료 3회 구간에만 적용한 1,000게임 후보는 같은 덱 보정 기준 정책 대비 +0.009점이었다. 상위 두 서로 다른 행동의 값 차이가 0.5 이하인 상태에만 심화한 후보도 개선되지 않았다. 이들은 최종 정책에 채택하지 않았다. 단순히 탐색 깊이를 더하는 대신 종단 가치의 오차를 줄이는 일이 중요하다는 실험상의 경고로 해석했다. 모든 심화 탐색이 무효라는 일반 명제는 아니다.

### 3.3 세 장·네 장 상호작용 확장

cap4 보조 문제에서 기존에 버렸던 세 장 이상의 손패 값도 저장하여 비교했다. 같은 1,500게임 개발 은행에서 기존 계수에 세 장 항을 추가한 후보들은 약 1856, 1854, 1830점이었다. 비교 기준 정책은 1859.036점이었다. 네 장까지 직접 조회하고 다섯 장을 포함-배제 또는 한계가치로 추정한 후보들은 약 1818~1845점으로 더 낮았다.

이는 해당 지평·계수·다섯 장 외삽 방식의 결과다. 더 큰 가치 모델이 원리적으로 열등하다는 증명은 아니다. 불리한 후보도 기록에 남겼고 최고 개발 점수만 최종 결과로 보고하지 않았다.

## 4. 다섯 장 전체 모델: 실제 확보한 범위

손패 한도가 실제 게임과 같은 cap5 보조 계산기를 구현했다. 효과 22종에서 중복을 허용한 0~5장 손패는 **80,730개**다. 단, 드로우는 여전히 전체 30장 분포의 IID 근사다.

이 계산기는 두 자원 상태의 가치 층, 드로우 기대값, chance backup 버퍼만 사용하도록 바꾸었다. 같은 자원 지평의 free-card 전이는 손패 크기가 작은 층부터 계산하고, 드로우 기대값은 반복 중 고정한다. 불필요한 큰 출력 버퍼를 제거하여 계산 작업 메모리를 약 3.2GB로 줄였다.

### 4.1 계산기 검증

같은 메모리 절약 방식을 cap4에 적용하여 원래 cap4 계산기와 비교했다. 잔여 횟수 0~2, 보너스 두 상태, 표본 위치 94개에서 **8,431,800개 손패 값**을 검사했다. 양자화 포함 최대 차이는 0.0157471로, 사전에 둔 0.02 허용치를 통과했다. 손패 인덱스 80,730개도 모두 대조했다.

파일명의 `exact`는 손패를 전부 열거한다는 의미다. 반복 허용오차 0.001, float32, 1/32 단위 저장 정밀도를 사용하므로 수학적으로 인증된 정확한 실제 게임 최적값은 아니다.

### 4.2 완료된 지평과 성능

**이번에 완료하고 평가한 cap5 지평은 12까지**다. 최초 작업 파일의 예정 헤더가 24인 것과 구분해야 한다. 지평 24의 cap5 완성 모델을 얻었다고 주장하지 않는다.

같은 개발 은행의 1,000게임에서 다섯 장 직접 조회·가중치 1·덱 잔차 없음 정책은 지평 8에서 **1812.707**, 지평 12에서 **1851.141**이었다. 더 긴 지평에서 개선은 있었지만 선정한 v2를 대체할 성능 근거는 아직 없다. 12회 모델 평가에는 약 466초가 걸렸다. 이는 4GB 메모리 한도에서 여러 대규모 평가와 동시에 실행한 결과이며, 일반적인 하드웨어 지연시간 보장이 아니다. 메모리 매핑의 반복 I/O 부담이 컸다.

지평 12의 작은 ≤2장 투영을 비교하면, 동일 계수에서 cap4 기반은 1841.060, cap5 기반은 1831.311이었다. 대응 차이 -9.749의 95% 구간은 [-22.5707, 3.0727]로 0을 포함한다. 작은 표본의 이 결과로 모델 용량의 우열을 확정하지 않았다.

### 4.3 재개용 체크포인트

별도로 제공하는 `adventure_dp5_h12_checkpoint.qdelta.gz`에는 지평 12의 두 가치 층을 담았다. 약 936MB의 원시 수치를 차분·byte-plane 변환 후 gzip으로 저장한 **무손실 체크포인트**다. 게임용 전체 모델이 아니며 기본 에이전트에 필요하지 않다.

전체 **5,798개 행·468,072,540개 양자화 값**을 원래 모델과 대조하여 저장/복원의 완전 일치를 확인했다. 후속 층 계산용 `advance-five.cpp`와 형식 설명을 동봉했다. 후속 13~24회 계산을 실제 완주·평가한 것은 아니므로 해당 코드의 컴파일 확인과 전체 후속 연구 완료를 구분한다.

메모리 제한을 넘은 초기 시도 및 중단된 탐색 실행은 `aborted-runs.json` 등에 별도로 기록했다. 중단 실행을 완료된 성능 표본으로 집계하지 않았다. 재개 시 저장 정밀도와 이후 층 계산이 일치하도록 r≥4에서 체크포인트 정밀도 반올림을 적용한다.

## 5. 원본 엔진 및 배포 정책 검증

원본 게임 파일 다섯 개의 SHA-256을 다시 확인했고 모두 변경되지 않았다. 원본 Board와 참조 구현의 테이블 **37,798건**, 상태 전이 **265,267건** 검사도 재실행했다.

최종 v2 JavaScript를 원본 `Board.js`에서 **1,024게임** 실행했다. C++과 모든 게임의 score·행동 수가 동일했고, 행동·점수 시퀀스의 누적 해시는 두 구현 모두 **1300119489**였다. 불법 행동과 게임 상태 직접 변경 검사를 통과했다.

추가로 드로우 후 덱 잔차 기대값의 열거 비교 200건, RNG가 호출되면 예외를 내도록 한 상태에서의 합법 행동/비변경 검사 100건을 통과했다. 패키지에서 새로 빌드한 네이티브 실행기도 별도 128게임으로 연구 바이너리와 대조했다. 해시/표본 테스트는 형식적 전 상태 동등성 증명을 대신하지 않는다.

초기 JavaScript 이식에서 덧셈·뺄셈 괄호 순서 때문에 동점 선택의 해시가 달랐던 부분은 최종 검증 전에 맞췄다. 단순히 최종 점수가 같다는 이유만으로 시퀀스 일치를 주장하지 않았다. 네이티브 캐시 최적화도 비최적화 구현의 256게임 trace hash와 같은 것을 확인했다.

## 6. 최종 평가 절차

시작 시드 **2726090800**, 총 100,000개의 게임을 네 shard로 나누었다. 각 게임 초기 PRNG는 `mix(baseSeed + episode)`다. 실제 엔진은 v1과 같은 canonical 단일 Mulberry32 stream을 주사위와 드로우에 사용했다. 평가 중 시드나 미래 결과는 에이전트 입력에 포함하지 않았다.

계수·모델·지평·표본 수는 최종 실행 전에 고정하여 `final-evaluation-plan.json`에 저장했다. 새 테스트 결과를 보고 계수를 바꾼 뒤 같은 은행을 독립 평가라고 부르지 않았다. 두 정책 각각 100,000게임 전부를 기록하고, seed를 일치시킨 점수 차이로 대응 신뢰구간을 계산했다. 신뢰구간은 게임 단위 독립 표본 근사를 사용하는 Monte Carlo 오차 추정이다.

## 7. 배포와 후속 연구의 기준선

실행 방법은 `README.md`, 고정 설정은 `agent/config.json`, 모델 및 파일 해시는 각 manifest에 있다. 최종 실행 모델은 **v1과 동일한 96,560,579바이트 gzip 모델**이며, 큰 cap5 모델로 바꾼 것이 아니다. Node.js는 외부 npm 패키지 없이 실행한다. 메모리 매핑 실험 모델과 최종 실행 모델의 크기·성능을 혼동하지 않아야 한다.

이번에 확보한 확정 기준선은 **1863.96061점**이다. 다음 목표는 1880이며, 남은 약 16점은 모델의 실제 비복원 덱·다중 손패 상호작용과 장기 가치 오차를 더 줄여야 한다. 더 긴 cap5 계산을 재개할 수 있는 상태를 보존했지만, 단순 용량 증가만으로 목표를 보장하지 않는다. 실제 덱과 손패를 함께 조건으로 하는 잔차 학습, 정확한 교사 값을 빠르게 조회할 수 있는 압축/증류, 별도 새 평가 은행의 검증이 다음 실험의 우선 대상이다.

**최종 판정:** 평균 1860의 1차 목표 통과. 평균 1880은 미달. 전역 최적성 미증명.
