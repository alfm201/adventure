## 1. 결론

규칙 감사, 독립 참조 구현 검증, 여러 가치 모델과 탐색 정책 구현, 후보 선택, 고정 정책의 독립 100,000게임 평가까지 수행했다.

선정 정책의 최종 평균은 **1857.11013점**이고, 표본 표준편차는 **202.73817**, 표준오차는 **0.64111**이다. 정규근사 양측 95% 신뢰구간은 **[1855.85355, 1858.36671]**이다.

**이번 후보는 1860 목표를 달성하지 못했다.** 점추정 기준으로 1차 목표까지 2.88987점, 2차 목표까지 22.88987점 남았다. 95% 신뢰구간의 상단도 1860보다 낮다. 소표본 탐색에서 관측된 1860대 점수를 최종 성능으로 보고하지 않는다.

전역 최적 정책을 찾았다는 주장도 하지 않는다. 현재 성과는 원본 규칙에 맞는 실행 가능한 정책, 재현 가능한 평가 체계, 그리고 검증된 1857.11점 기준선을 확보한 것이다. 1880의 달성 가능성 또는 불가능성은 이번 실험으로 판정되지 않는다.

## 2. 소스에서 확정한 게임 정의

### 점수와 종료

`score`는 누적 보상이 아니라 현재 보드 위치다. 초기값은 1이고 보드 크기는 2898, 스테이지 수는 75다. 평가 목적은 게임 종료 시의 위치 `score`의 기대값이다. 보드 끝에 도달하는 것 자체는 `terminal` 조건이 아니다.

실제 종료 조건은 `diceUse >= 100 && !isDouble`이다. 따라서 100번의 행동으로 끝나는 게임이 아니다. 고정 이동 카드와 다음 스테이지 카드는 주사위를 소비하지 않으며, 더블에 의한 추가 주사위도 있다. 100번째 유료 주사위가 더블이 아니면 그 행동 이후에 카드를 추가로 사용할 수 없다. 그 행동의 도착 효과는 먼저 처리된다.

현재 더블 보너스가 없을 때 주사위를 던지면 유료 횟수를 1 올리고, 같은 눈이면 보너스를 하나 만든다. 이미 보너스가 있을 때 던진 주사위는 유료 횟수를 올리지 않고 보너스를 해제한다. 이 경우 다시 같은 눈이 나오더라도 더블이 연쇄되지 않는다.

### 이동과 타일

일반 주사위 이동은 앞으로 만나는 첫 event 6 또는 9 타일을 넘지 못한다. 카드 이동은 이 일반 이동의 정지 규칙을 거치지 않는다. event 4 점프는 연속해서 해소되고, 최종 도착 타일이 event 2이면 손패 여유가 있을 때 카드를 얻는다.

제공된 커널에서 event 1, 3, 5에는 별도의 상태 변경 동작이 없다. 보드 데이터의 이벤트 번호에 다른 게임의 통상적인 의미를 덧붙이지 않았다.

### 카드와 덱

카드는 총 30개 ID로 구성된다. 고정 이동 카드, 주사위 합에 배수를 곱하는 카드, 다음 스테이지 카드의 세 종류다. 같은 type/value인 카드를 효과별로 묶으면 22종이다. 실제 행동은 카드 종류가 아니라 현재 손패의 1-based 슬롯을 선택한다.

손패는 최대 5장이고, 드로우는 현재 `deckMask`에 남아 있는 ID 중 균등 선택이다. 사용한 카드가 즉시 덱에 돌아가는 구조가 아니다. 덱을 모두 뽑으면 전체 30개 ID로 즉시 재생성된다. 이 재생성에는 현재 손패의 ID도 포함되므로, 서로 다른 덱 주기에서 같은 ID를 중복 보유할 수 있다. 따라서 손패를 단순 ID 집합으로 처리하면 안 된다.

**소스 근거:** `engine/board.js`, `engine/tables.js`, `rules/index.js`, `rules/card-data.js`, `rules/board-data.js`. 동봉한 원본 파일의 SHA-256은 `source-manifest.json`에 있다.

## 3. 문제의 수학적 정의

관측 가능한 상태를 다음과 같이 두었다.

```
s = (p, r, b, H, D)
p: 현재 위치
r: 남은 유료 주사위 횟수 = 100 - diceUse
b: 현재 더블 보너스 여부
H: 중복을 허용하는 손패
D: 현재 남은 덱
```

행동 집합은 `{0, 1, ..., cardCount}`다. 0은 일반 주사위, 나머지는 손패 슬롯이다. 정책은 환경의 난수 함수, 시드, 미래 주사위 값을 읽지 않는다. 남은 덱은 현재 상태 또는 관측된 드로우 이력으로 알 수 있다는 조건이다. 다른 관측 제한을 가진 환경에서는 별도의 정책과 평가가 필요하다.

목적은 `J(pi) = E_pi[p_terminal]`이다. 종료 상태의 가치는 현재 위치이고, 비종료 상태의 최적 가치는 각 합법 행동의 다음 상태 가치 기댓값 중 최대다. 이동량을 보상으로 쓰는 대안도 가능하지만 그때는 할인 없이 합산해야 최종 위치와 일치한다. 임의의 할인율이나 카드 획득 보너스를 실제 평가 점수에 추가하지 않았다.

균등한 독립 6면체 두 개를 가정하면 합 d의 조합 수는 `6 - |7-d|`다. 보너스가 없는 상태에서 짝수 합에는 더블 조합이 정확히 하나 있으므로 합과 더블의 결합확률을 함께 사용해야 한다. 주사위 합과 더블 여부를 독립적으로 추출하는 근사는 쓰지 않았다.

## 4. 선택한 정책

### 4.1 보조 동적계획법 모델

전체 실제 상태 공간을 그대로 전부 저장하는 대신, 손패 최대 4장과 전체 30장 분포의 복원 추출을 사용하는 보조 문제를 계산했다. 계획 지평은 유료 주사위 24회이며 보너스 상태는 별도로 계산한다. 원본 게임의 5장 한도와 비복원 덱은 이 보조 문제에 완전히 포함되지 않는다.

효과가 같은 카드 ID를 묶은 22종으로, 최대 4장 손패는 중복을 허용하는 조합 14,950개다. 주사위를 쓰지 않는 카드 사용과 카드 재획득 때문에 같은 자원 지평 안에 의존성이 있으므로 반복 계산으로 처리했다. 구현의 수치적 정지 허용치는 0.001이다. 이것은 전역 최적성의 오차 인증이 아니다.

모든 지평의 전체 손패 가치를 저장하지 않고, 계산 중 필요한 층을 재사용한다. 결과로는 각 위치·남은 횟수·보너스 상태에서 빈 손패, 한 장 손패, 두 장 손패의 276개 값만 보존한다. 보조 문제의 확률모형이 실제 게임과 다르므로 그 값은 실제 게임 최적값의 상한이나 하한으로 해석하지 않는다.

### 4.2 실제 손패의 근사 가치

빈 손패 가치를 B, 카드 c 한 장의 추가 가치를 U(c), 두 카드의 추가 상호작용을 Delta(c,d)라고 놓았다.

```
U(c)       = V({c}) - V(empty)
Delta(c,d) = V({c,d}) - V({c}) - V({d}) + V(empty)

V_hat(s) = B + 0.95 * sum U(c)
             + 0.95 * 0.75 * sum_{card pairs} Delta(c,d)
```

실제 3~5장 손패에도 이 표현을 사용한다. 따라서 명시적인 삼중·사중·오중 상호작용을 모두 복원하는 모델은 아니다. 보조 모델을 이용한 가치 근사이며, 나머지 오차는 실제 게임 시뮬레이션에서 판단했다. 최종 카드 종류별 추가 가중치와 드로우 가중치는 모두 1이다.

### 4.3 실제 규칙의 두 단계 기대값 탐색

선정 정책은 다음 연산에 해당한다.

```
Q1(s,a) = E[V_hat(s') | s,a]
Q2(s,a) = E[max_a' Q1(s',a') | s,a]
pi(s)   = argmax_a Q2(s,a)
```

첫 두 단계의 전이는 실제 덱 마스크, 실제 손패, 실제 더블·종료·착지 규칙을 사용한다. 주사위와 드로우 결과를 표본 하나로 고르지 않고 확률적으로 평균한다. 두 번째 행동은 첫 번째 결과를 본 상태에 맞게 선택한다. 미래의 숨겨진 결과를 먼저 보고 행동을 선택하는 방식이 아니다.

최종 탐색은 몬테카를로 표본 정책이나 MCTS가 아니다. 같은 관측 상태에는 같은 행동을 내는 결정론적 expectimax 정책이다. 실제 남은 횟수가 24보다 크면 가치표의 계획 창을 24로 두고, 탐색 안에서는 가상의 잔여 횟수를 일관되게 감소시킨다. 가치표가 근사치이고 창이 제한되어 있으므로, 두 단계 기대값 계산이 정확하다는 사실이 전체 정책의 최적성을 뜻하지 않는다.

## 5. 실제 실험 결과

후보·설정·모델을 고정한 뒤, 이전 선택 과정에서 사용하지 않은 시작 시드 1937719000의 100,000게임 은행을 실행했다. 각 게임의 실제 PRNG 초기값은 `mix(baseSeed + episode)`다. 원시 CSV의 `seed` 열은 이미 이 변환을 적용한 초기값이다.

| 정책 | 게임 수 | 평균 최종 score | 95% 신뢰구간 |
|---|---:|---:|---:|
| 일반 주사위만 사용 | 100,000 | 943.68135 | 943.30783~944.05487 |
| 튜닝한 단순 카드 휴리스틱 | 100,000 | 1784.97128 | 1783.77084~1786.17172 |

한 단계 정책 대비 평균 차이는 **+9.22537점**이다. 동일 초기 시드를 대응시킨 점수 차이의 95% 신뢰구간은 **[7.86859, 10.58215]**다. 이 개선은 최종 표본에서도 확인되었지만, 개선의 크기는 1860을 넘기기에 부족했다.

최종 정책의 중앙값은 1856, 하위 10% 위치는 1593, 상위 10% 위치는 2120이다. 최솟값은 1023, 최댓값은 2724였다. 평균 행동 수는 165.42222이며, 최대 219회였다. 평가 중 안전 행동 한도에 걸리거나 제외된 게임은 없었다.

한 게임이 1860 이상을 기록한 비율은 49.288%, 1880 이상 비율은 45.237%다. 이는 평균 기대 score 목표의 달성 여부와 다른 지표이며, 통과 기준으로 사용하지 않았다.

### 실패하거나 채택하지 않은 시도

초기 단순 휴리스틱은 별도 10,000게임에서 약 1482점이었다. 카드 획득 가치와 보존 기준을 조정해 1780대 기준선을 만들었다. 부정확한 종단 가치에 의존하는 짧은 몬테카를로 rollout은 한 설정의 1,000게임에서 1668.32점으로 오히려 악화됐다. 이 결과를 보고 단순히 샘플 수나 탐색 깊이를 늘리는 대신 가치 근사를 개선했다.

카드 1장 근사, 2장 모델, 3장 보조 모델과 4장 보조 모델을 단계적으로 비교했다. 계획 창을 무조건 늘리는 것도 항상 개선을 만들지는 않았다. 예비 선택 과정의 최고점만 보고하지 않고, 최종 고정 평가를 별도로 실행했다.

선정 후보는 1,000게임 예비 실험에서 1862.79점, 독립 10,000게임 검증에서 1859.3009점을 기록했지만, 최종 100,000게임에서는 1857.11013점이었다. 후보 선택과 표본 변동의 영향을 구분해야 한다는 직접적인 사례다. 예비 1862.79점을 목표 달성 근거로 쓰지 않는다.

## 6. 시뮬레이터와 배포 정책 검증

100,000게임 본평가는 C++ 연구용 시뮬레이터에서 수행했다. 이를 원본 JavaScript 실행과 구분한다.

- 독립적인 JavaScript 참조 구현과 원본 Board: 테이블 검사 37,798건, 실제 상태 전이 265,267건 대조.
- 동일 무작위 행동 실행에서 C++과 JavaScript의 전이 수 265,267건 및 누적 상태 해시 329317741 일치.
- 최종 정책을 원본 `Board.js`에서 1,024게임 실행. C++과 게임별 score 및 행동 수가 모두 일치.
- 최종 1,024게임의 행동·점수 시퀀스 누적 해시가 두 언어에서 모두 3985191187. 불법 행동과 게임 상태 직접 변경 검사는 통과.

해시 일치가 모든 가능한 상태에 대한 형식적 동등성 증명은 아니지만, 엔진 이식 오류나 정책 불일치에 대한 실제 검증 근거다. 또한 다섯 개 원본 게임 파일은 변경하지 않았다.

원본 JavaScript에서 1,024게임 검증은 69.13초였다. 이 측정은 네 개 C++ 평가를 동시에 실행한 조건이고, 로딩을 제외하며 상태 비변경 검사 등도 포함한다. 독립적인 배포 지연시간 보증으로 해석하면 안 된다.

값 테이블은 원시 160,024,804바이트이고 gzip 압축 모델은 96,560,579바이트다. 브라우저용 소형 모델은 이번 산출물에 포함하지 않았다. Node.js에서는 외부 패키지 없이 압축 모델을 읽어 실행할 수 있다.

## 7. 남은 격차를 줄이는 다음 연구

### 우선순위 A — 덱 조건부 장기 가치

최종 탐색의 첫 두 단계는 현재 덱을 반영하지만 가치표의 장기 드로우는 전체 덱 복원 추출 근사다. 실제 덱의 배수 카드 잔량, 카드 효과별 잔량, 덱 재생성 시점에 따른 장기 가치 오차를 먼저 측정하는 것이 합리적이다. 효과별 덱 카운트와 손패를 입력으로 받는 잔차 가치 모델을 현재 DP4 위에 추가하는 후보가 있다.

```
V_residual(s) = V_DP4(s) + f_theta(position, remainingDice, bonus, handCounts, deckCounts)
```

이는 아직 구현·학습·검증한 최종 정책이 아니라 다음 실험 설계다. 현재 정책의 실제 궤적과 모델 기반 Bellman 목표, 최종 결과를 함께 사용해 보정하고, 별도 시드에서 실제 기대 score가 개선되는지 확인해야 한다.

### 우선순위 B — 3~5장 상호작용과 종료 구간

현재 배포 가치 표현은 두 카드 상호작용까지만 명시적으로 사용한다. 삼중 카드 연계가 중요한 상태와 한 단계·두 단계 정책의 선택이 갈리는 상태를 모아 추가 계산의 가치가 큰지 측정한다. 잔여 유료 주사위가 1~3회인 도달 상태에 대해서는 실제 덱을 포함한 메모이제이션 탐색과 계산량 제한을 실험한다. 마지막 주사위 이후 카드를 쓸 수 있다고 가정해서는 안 된다.

### 우선순위 C — 선택적 심화 탐색과 모델 경량화

모든 상태에 동일한 추가 탐색을 적용하기보다, 상위 후보 행동의 가치 차이가 작거나 손패 연계가 많은 상태에 연산을 집중하는 방식을 비교한다. 더 깊은 탐색이 항상 좋은 것은 아니므로, 탐색 깊이별·종단 가치별 제거 실험이 필요하다.

배포 크기를 줄이려면 정확한 탐색 정책을 교사로 한 정책 또는 가치 모델 증류도 검토할 수 있다. 다만 압축률이나 속도만으로 채택하지 않고 원래 평가 점수와 경계 상황의 행동 일치를 함께 측정해야 한다.

### 검증 절차 유지

이번 최종 테스트 은행을 다시 학습·튜닝용으로 사용한 뒤 같은 은행을 새로운 독립 최종 테스트라고 부르면 안 된다. 새로운 후보는 새 시드 은행에서 고정 표본 수로 검증한다. 1차 목표는 평균 1860, 도전 목표는 1880을 유지하고, 보수적인 통과 기준으로 양측 95% 신뢰구간 하한이 해당 목표 이상인지도 함께 기록한다.

## 8. 재현 파일과 참고 맥락

실행 방법은 `README.md`, 고정 설정은 `agent/config.json`, 최종 평가 계획은 `results/final-evaluation-plan.json`, 모든 집계는 `results/final-summary.json`에 있다. `results/final-100000.csv` 및 세 기준 정책의 CSV는 전체 게임을 포함한다. 모델 무결성은 `model/manifest.json`과 원본 파일 매니페스트로 확인할 수 있다.

이 연구의 게임 규칙과 실험 결과는 제공된 소스 및 여기서 실행한 코드에 근거한다. 외부 이론적 맥락으로는 Bertsekas의 *Biased Aggregation, Rollout, and Enhanced Policy Improvement for Reinforcement Learning* (2019, arXiv:1910.02426), *On-Line Policy Iteration for Infinite Horizon Dynamic Programming* (2021, arXiv:2106.00746)를 참고했다. 이들 연구의 특정 수렴 보장을 본 보조 문제·가치 근사·유한 계획 창에 그대로 적용하지 않는다.
