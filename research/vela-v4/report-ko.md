## 2. 이번에 실제로 복원하고 계산한 범위

직전 응답과 달리 이번에는 계산 환경을 사용할 수 있었다. 이전 압축 파일, 모델 체크포인트, 원본 엔진 및 CSV를 직접 읽고 실제 코드를 실행했다.
다만 첨부에는 v3의 23.4GB 전체 실행 표가 없었다. 보존된 것은 지평 24의 두 보너스 상태 가치 층이었다.

이번에는 그 체크포인트를 이용해 별도 정책을 구성했다. **다섯 장 DP를 지평 25 이상으로 확장하거나, 지평 0~24 전체를 다시 생성했다고 주장하지 않는다.**
카드 효과 22종의 0~5장 손패 80,730개에 대한 지평 24 값은 직접 사용하고, 다른 잔여 주사위 수의 값은 기존 네 장 보조 모델의 시간 변화량으로 보정한다.

## 3. 가치 함수와 두 단계 탐색

위치 p, 잔여 유료 주사위 r, 더블 보너스 b, 손패 H, 남은 덱 D를 사용한다.
원본 게임의 유료 주사위 한도는 계속 100이며, 손패는 5장이고 드로우는 비복원 추출이다.
정책 내부 계획 창만 `min(실제 잔여 유료 주사위, 24)`로 제한한다.

네 장 보조 문제의 빈 손패·단일 카드·두 카드 값을 투영한 함수를 A4라고 하면,

```text
A4(r,b,p,H) = B4 + 0.975 * (sum(U4) + 0.75 * sum(pairInteraction4))
alpha(r,b) = min(1, (r+b)/12)
Vhat(s) = A4(r,b,p,H)
        + alpha(r,b) * (F5(24,b,p,H) - A4(24,b,p,H))
        + DeckPotential(D,r,b)
```

여기서 F5는 보존된 다섯 장 전체 손패 가치다. `alpha`는 종료 직전에 오래 남은 자원의 손패 보정을 그대로 적용하지 않도록 줄이는 계수다.
지평 24에서는 덱 보정 전 값이 저장된 F5 값과 일치한다. 다른 지평에서는 정확한 다섯 장 DP값이 아니라 시간 보정 근사다.

덱 보정은 기존의 중심화 카드 계수 a_i를 유지했다.

```text
DeckPotential = 0.6 * min(1, 0.7*(r+b)/deckCount) * sum(a_i for i in deck)
```

드로우한 경우 해당 카드가 빠진 덱과 마지막 카드의 덱 재생성도 반영한다. 종단 상태의 값은 위치 그 자체이며, 손패 또는 덱 가치를 추가하지 않는다.

선택은 두 단계 기대값 탐색이다.

```text
Q1(s,a) = E[Vhat(s') | s,a]
Q2(s,a) = E[max_a' Q1(s',a') | s,a]
policy(s) = argmax_a Q2(s,a)
```

첫 두 행동의 주사위 합·더블, 카드 제거, 점프, 도착 이벤트, 비복원 드로우와 덱 재생성은 원본 규칙을 적용한다.
다만 그 이후의 가치에는 보조 모델의 IID 드로우와 유한 계획 창 근사가 남는다.
정책은 현재 공개 상태만 입력받고 미래 난수나 게임 시드는 입력받지 않는다.

## 6. 지난 종료 구간 초안의 실제 구현과 검증

별도 C++ 종료 탐색기와 JavaScript 연결 모듈을 구현했다.
최종 score의 실제 기대값을 종료까지 계산하며, 현재 덱의 비복원 추출을 보존한다.
현재 상태의 모든 행동 및 확률 분기를 끝까지 계산한 경우에만 해당 행동을 채택하고, 예산을 초과하면 기존 에이전트로 돌아간다.

완료된 상태만 캐시하며 게임 도중에는 캐시를 비우지 않는다.
완료된 상태의 모든 가능한 비종단 후속 상태도 이미 계산되어 있어, 캐시가 가득 차도 그 후속 행동을 조회할 수 있다.
정확한 실수 연산과 올바른 전이를 가정하면, 완료된 상태에서 최적 행동을 계속 따르는 이 전환은 기준 정책의 기대값을 낮추지 않는다.
이 설명은 부동소수점 오차까지 형식적으로 인증했다는 주장이 아니다.

### 64비트 상태 키

같은 type/value 카드는 효과별로 묶었다. 8종은 각 두 장, 14종은 각 한 장이므로 덱 잔량 공간은 `3^8 * 2^14 = 107,495,424`이다.
상태 키의 비트 배치는 다음과 같다.

```text
위치 12비트 + 잔여 유료 주사위 7비트 + 보너스 1비트
+ 손패 순위 17비트 + 효과별 덱 코드 27비트 = 64비트
```

80,730개 손패의 순위와 키 중복을 전수 검사했다. 무작위 덱 100,000개의 효과별 잔량 2,200,000건도 대조했다.
이 표현은 효과별 전이 확률을 보존한다. 서로 다른 원본 ID를 같은 난수로 뽑는 시퀀스 자체를 같게 만든다는 뜻은 아니다.
실제 행동은 해당 효과를 가진 원본 손패 슬롯으로 복원한다.

### 종료 모듈의 효과는 작았다

같은 500게임 개발 표본에서 H48은 1867.044점, 잔여 1회 종료 탐색을 붙인 후보는 1867.194점이었다.
대응 차이는 +0.15점이고, 95% 신뢰구간은 약 -0.084~+0.384점이다. 표본만으로 양의 개선을 확정할 수 없다.
잔여 2회와 더 큰 탐색 예산을 사용해도 같은 점수열을 얻었다.
확장 상태 수는 4,937,936개에서 67,124,588개로 늘었지만 이 표본의 최종 점수는 추가로 개선되지 않았다.

따라서 이 모듈을 1880 돌파의 주된 근거로 사용하지 않았다. v4 주 정책의 최종 성능과 종료 모듈의 개발 실험은 별개다.

## 8. 최종 평가 절차

최종 시드 은행은 4070909000이며 i번째 시드는 `mix(4070909000 + i)`이다.
50,000게임 표본 수와 선택 정책을 실행 전에 고정했다. 네 평가 프로세스는 서로 다른 게임을 실행하고 각 게임은 독립 난수 스트림을 유지한다.
정책 설정, 평가 실행 파일 해시, 시드 및 표본 수는 `results/final-evaluation-plan.json`과 각 평가 폴더의 `plan.json`에 기록했다.
실행 도중 점수에 따라 정책이나 표본 수를 바꾸지 않았다.

H48 대조군은 새 은행의 첫 10,000개 시드에서 실행했다. v3 비교는 기존 첨부 CSV를 재집계했다.
평균과 대응 차이의 신뢰구간은 게임 단위 표준오차에 1.96을 곱했다.
서로 다른 은행의 v3와의 차이는 두 표본 평균의 분산 합을 사용했다.

전체 게임 행동 수 안전 한도는 1040이다. 기본 초기 손패가 비어 있고 보너스가 연쇄되지 않으므로 최대 주사위 던지기는 200회다.
완전히 소진한 덱을 C, 배수 카드 사용을 U라고 하면 `6C <= U+5 <= 205`이므로 C는 34 이하이다.
무료 카드는 소진 덱과 마지막 부분 덱에서 최대 `24(C+1) <= 840`장이다. 따라서 행동 수는 200+840 이하이다.
이는 보수적 상한이며 실제 가능한 타이트한 최대치를 찾았다는 뜻은 아니다.

## 9. 실행 자료와 남은 과제

실행법은 `README_KO.md`를 참조한다. 전체 실행 패키지에는 필요한 세 압축 모델이 포함된다.
모델 복원은 체크포인트 디코딩과 네 장 모델 압축 해제이며, 거대한 DP를 처음부터 재계산하는 작업이 아니다.
종료 탐색은 `agent/endgame-wrapper.mjs`로 기존 정책에 별도로 연결할 수 있다.

현재 검증되지 않은 부분은 실제 비복원 덱을 포함한 장기 가치, 다섯 장 지평 25 이상의 정책 효과, 전역 최적값이다.
종료 구간 실험의 작은 개선량을 고려하면 다음 유력한 연구 대상은 남은 덱이 작은 구간의 조건부 탐색과 장기 가치 오차다.
그 효과나 1880 달성 여부를 미리 수치로 보장하지 않는다.
