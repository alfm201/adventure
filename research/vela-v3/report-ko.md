## 2. 이번 정책에서 달라진 것

v2는 최대 네 장의 손패를 가진 보조 문제를 풀고, 빈 손패·한 장·두 장 가치로 실제 다섯 장 손패를 근사했다. v3는 **최대 다섯 장의 손패 조합 전체에 대한 가치표를 직접 사용**한다.

30개 카드 ID는 효과 기준 22개 클래스로 묶을 수 있다. 덱 재생성 때문에 같은 효과 또는 같은 ID가 중복 보유될 수 있으므로 중복 조합을 허용한다. 빈 손패부터 다섯 장까지의 클래스 손패 수는 80,730개다. 네 장 이하의 14,950개보다 약 5.4배 많다.

| 설정 | v2 | v3 |
|---|---|---|
| 보조 문제의 손패 한도 | 4 | 5 |
| 실제 손패 가치 표현 | 단일·두 카드 상호작용 투영 | 0~5장 손패 가치 직접 조회 |
| 보조 문제 계획 지평 | 24회 | 24회 |
| 온라인 기대값 탐색 | 2단계 | 1단계 |
| 손패 가치 전체 가중치 | 0.975 | 1.0 |
| 덱 보정 계수 | 0.6 | 0.6 |
| 덱 보정의 드로우율 계수 | 0.7 | 0.7 |

이 비교에는 여러 설계 변경이 함께 포함된다. 개선량 전체를 특정 한 가지 변경의 인과 효과로 해석하지 않는다.

### 가치 모델의 범위

보조 가치표는 위치, 남은 유료 주사위 횟수, 보너스 여부, 정규화된 손패를 사용한다. 실제 게임의 손패 한도와 같은 다섯 장을 다루지만, **미래 드로우는 전체 30장 분포의 IID 복원 추출**로 근사한다. 전체 게임의 100회를 완전히 푼 모델이 아니라, 온라인에서 `min(남은 유료 주사위, 24)`를 사용하는 모델이다.

정책은 각 합법 행동의 다음 상태에 대해 다음 값을 확률적으로 평균하고 가장 큰 행동을 선택한다.

`보조 DP5 가치 + 남은 덱의 가치 보정`

실제 첫 행동의 주사위 합·더블 결합확률, 착지·점프·카드 획득, 비복원 덱과 덱 재생성, 종료 조건을 적용한다. 다음 상태가 종료 상태라면 손패 가치와 덱 보정을 더하지 않고 그 위치만 반환한다. 미래 난수, 게임 시드 또는 다음 덱 순서는 입력받지 않는다.

덱 보정은 v2와 같은 형태다.

`D_hat = 0.6 * min(1, 0.7 * (r + b) / deckCount) * sum(centeredCardValue[id])`

여기서 r은 내부 계획 구간의 남은 유료 주사위 수, b는 보너스 여부다. 카드 기준값은 v2에서 사용한 중심화 계수를 유지했다. 한 장 남은 덱을 드로우한 뒤에는 전체 덱으로 재생성되는 효과도 반영한다. 이 항은 실제 덱 조건부 최적값 자체가 아니라 보정이다.

따라서 첫 행동의 확률 계산과 손패 표 조회가 정확하더라도, 그 이후의 IID 근사·유한 지평·덱 보정까지 포함한 정책이 원래 게임의 전역 최적 정책이 되는 것은 아니다.

## 3. 계산기와 저장 방식

현재 세션에 유지된 첨부에는 이전의 다섯 장 지평 12 체크포인트가 없었다. 기존 계산기 소스를 재사용·개선하여 다시 계산했고, **다섯 장 모델을 지평 24까지 완료**했다. 다섯 장 지평 32나 48의 완성 모델을 만들었다고 주장하지 않는다. 별도로 계산한 지평 48 모델은 네 장 모델이다.

계산 중에는 두 보너스 상태의 가치 층과 드로우 기대값, 주사위 기대값 버퍼를 사용한다. 같은 제거 손패에 대한 배수 주사위 계산을 재사용하고, 손패 차원에서 벡터화했다. 유료 주사위를 쓰지 않는 카드 연계는 같은 자원 구간 내 반복 계산으로 처리한다.

연구 중 지평 2까지 완료한 뒤 드로우 계산을 벡터화한 구현으로 전환했다. 이때 **저장된 1/32 단위 양자화 값에서 한 번 재시작**했다. 이후 지평 3~24는 재개된 계산을 이어갔다. 이 이력을 숨기지 않도록 재생성 스크립트도 `0~2 계산 → 헤더 확장 → 지평 2에서 재개`의 같은 절차를 사용한다.

저장 파일은 손패 크기별로 분리한다. 빈 손패는 float32, 나머지는 빈 손패 대비 차이를 1/32 단위 int16으로 저장한다. 명목상 한 값의 저장 반올림 오차는 최대 1/64점이다. 이는 보조 문제의 수렴 오차나 실제 게임에 대한 근사 오차 전체를 1/64로 제한한다는 뜻이 아니다.

실행에 필요한 여섯 개 tier 파일의 총 크기는 **23,403,917,092바이트, 약 23.404GB**다. 연구용 두 카드 투영 파일은 별도다. 계산은 메모리 제한 4GiB, CPU 할당 4코어 환경에서 수행했고, 계산기의 작업 메모리는 약 3.2GB였다.

## 5. 최종 평가 절차와 평가기 변경

기본 시드 은행은 3809081000이며, i번째 게임의 시드는 `mix(baseSeed + i)`로 만든다. 각 게임은 원본과 같은 단일 Mulberry32 난수 스트림을 유지한다. 주사위와 카드에 별도 난수 스트림을 배정한 초기 개발 실험은 최종 결과에 섞지 않았다.

정책 설정과 표본 수를 먼저 기록했다. 최종 평가 도중 변경한 것은 **게임 실행 순서**뿐이다. 전체 가치표의 I/O 비용을 줄이기 위해 여러 게임을 남은 유료 주사위 수별로 교차 실행했다. 게임마다 독립된 상태와 RNG를 유지하고, 점수·행동 기록은 다시 게임 순서로 출력한다.

변경 전후를 원본 JavaScript 엔진의 1,024게임과 대조하여 모든 게임의 score·행동 수와 전체 행동·점수 해시가 일치하는 것을 확인한 뒤 고정된 100,000개 시드 전부를 다시 평가했다. 이전에 중단한 실행의 부분 기록을 최종 표본에 더하지 않았다. 표본 수를 점수에 맞춰 줄이거나 늘리지 않았다.

평균 신뢰구간은 게임 단위 표본의 표준오차에 1.96을 적용했고, 정책 차이는 같은 시드의 점수 차이에 동일한 계산을 적용했다. 이는 시뮬레이션 표본에 대한 통계적 추정이지 기대값의 수학적 증명이 아니다.

근거: `results/final-evaluation-plan.json`, `results/final-scheduler-amendment.json`, 원시 CSV와 검증 JSON.

| 항목 | 지평 48 후보 | 같은 20,000시드의 v2 |

## 8. 산출물과 실행

### 주 정책 v3

연구 패키지는 원본 엔진, C++ 정책, Node.js 브리지, 모델 계산기, 평가기, 검증 코드와 결과를 담는다. **23.4GB짜리 전체 실행 가치표는 ZIP에 포함하지 않았다.** 체크포인트만으로 이 에이전트를 바로 실행할 수도 없다. 제공된 재생성 절차 또는 동일한 전체 tier 파일이 필요하다.

```bash
bash research/build.sh
bash research/build-model.sh 4
node demo.js
```

재생성 절차는 비어 있는 모델 디렉터리에서 시작하고, 지평 2에서 한 번 양자화 재시작하는 실험 이력을 반영한다. 완료 후 제공된 전체 파일 SHA-256과 대조한다. 빌드에는 C++17/OpenMP 지원 컴파일러와 Python 3가 필요하다. 이 연구의 컴파일러는 g++ 14.2.0이었다. Node.js 실행 경로에는 npm 패키지를 설치하지 않는다. 실험용 회귀 분석 코드는 별도로 NumPy를 사용한다.

주 정책의 인터페이스는 비동기다.

```js
while (!board.terminal) {
  board.step(await agent.choose(board));
}
```

반환값은 0 또는 현재 손패의 1-based 슬롯이다. v3는 네이티브 워커를 사용하는 Node.js 에이전트이며 브라우저 단독 실행 정책은 아니다.

### 별도 지평 48 후보

실행 모델을 포함한 ZIP을 압축 해제하고 `node demo.js`를 실행한다. 이 정책은 기존과 같은 동기식 `agent.choose(board)` 인터페이스다. 이 ZIP으로 얻는 정책 성능은 위 20,000게임 후보의 결과이지 v3의 1873.62695점 결과가 아니다.

### 지평 24 체크포인트

두 gzip 파일을 순서대로 복원하면 지평 24의 보너스 두 층이 나온다. 압축 전 크기는 936,168,296바이트다. 저장된 양자화 값 **468,072,540개 전체**를 원본 저장값과 비교하여 손실 없는 압축·복원을 확인했고, 후속 계산기의 로더에서도 읽기 검사를 통과했다.

```bash
bash research/restore-checkpoint.sh PART1.qdelta.gz PART2.qdelta.gz model/h24.qdelta
```

이 체크포인트는 이후 지평 계산을 재개하기 위한 상태다. 지평 0~23의 전체 가치표를 포함하는 실행 모델은 아니며, 지평 25 이상의 계산을 이번에 완료했다는 뜻도 아니다. 검증에서는 후속 층을 계산하지 않고 로더만 실행했다. 체크포인트의 무손실 압축과 앞서 설명한 가치표 자체의 양자화 오차는 구분해야 한다.

## 9. 남은 연구 과제

1880까지의 현재 격차는 **6.37305점**이다. 다음 실험의 우선 대상은 다섯 장 모델의 더 긴 계획 구간, 실제 비복원 덱을 반영하는 장기 가치 보정, 새 배치 실행기에서의 선택적 추가 탐색이다. 어느 접근이 얼마나 개선할지는 아직 확인하지 않았다.

실행 부담을 줄이기 위한 압축·증류도 중요하다. 이번 선형 회귀 기반 축소 후보는 그대로 채택하지 않았다. 향후 축소 모델은 값의 평균 오차뿐 아니라 실제 행동 선택과 독립 게임 score를 함께 평가해야 한다.

이번 100,000게임 은행을 앞으로 튜닝에 사용한다면, 그 이후 후보의 최종 평가에는 또 다른 은행이 필요하다. **확정된 새 기준선은 1873.62695점이며, 1880은 아직 남아 있다.**
