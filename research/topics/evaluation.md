# 평가와 공통 기준

[연구 전체 흐름](../README.ko.md) · [Research overview](../README.md) · [출처](sources.md)

주요 평가 목표는 관측 가능한 상태만으로 행동을 선택해 평균 최종 점수를 높이는 것입니다. 다른 목표나 규칙을 완화한 게임의 결과는 별도로 표시합니다. 이 문서는 상태·정책·성능 수치를 해석할 때 필요한 공통 기준을 정리합니다.

## 상태와 정책을 함께 명시

- 점수는 게임 보드의 현재 진행 위치이며 주목표는 **종료 시점의 값**입니다. 잠깐 높은 위치에 도달한 것과 최종 점수가 높은 것은 다릅니다.
- `t`는 사용한 **유료 주사위 횟수**, `b`는 추가 굴림 여부입니다. 카드 사용과 무료 추가 굴림이 있으므로 행동 수와 `t`가 같지 않습니다. 실제 종료는 유료 주사위 한도와 추가 굴림 상태를 함께 봅니다.
- 실제 상태의 카드는 물리 ID 1–30과 잔여 30-bit 덱으로 구분합니다. 모델은 효과가 같은 카드를 클래스별로 묶을 수 있지만 물리 덱의 추출 확률과 입력·출력의 대응 관계가 유지되어야 합니다.
- 반환 행동은 주사위와 **현재 입력 손패 슬롯**을 구분합니다. 카드 사용 뒤 슬롯이 이동할 수 있습니다.
- 모델 이름과 함께 **가치 추정 방식·탐색 깊이·실제 덱 처리·보정 항목**을 적습니다. 같은 가중치를 사용해도 1-step과 2-step은 다른 정책입니다.

배열·패키지의 입출력 형식과 horizon 제한은 실행기별 정의를 따릅니다. [VELA 실행 소스](../../src/policies/vela/native/README.md), [LYRA 학습·변환](../lyra-v1/README.md)을 참고하세요.

## 점수를 읽는 기준

| 표현 | 뜻 | 혼동하면 안 되는 것 |
|---|---|---|
| 직접 정책 / standalone | 선택기를 그대로 계속 실행한 게임 성능 | 그 정책을 후속 정책으로 쓰는 root 추천 엔진 성능 |
| root rollout | 첫 행동별 후속 게임을 반복해 비교 | 미래 결과를 미리 아는 최적 경로 |
| $`Q^\pi`$ | 첫 행동 뒤 정책 $`\pi`$를 따를 때의 기대값 | 전역 최적 정책의 $`Q^{\ast}`$ |
| 국소 regret·행동 일치 | 특정 참조에서 행동 선택의 차이 | 전체 게임의 최종 점수 차이 |
| 원점수 평균 | 실제 완료 게임 점수의 평균 | 학습 손실·가치망 출력·진단 정답 평균 |
| 제어변량 보정 평균 | 평균을 보존하도록 설계한 통계 보정으로 변동을 줄인 추정 | 정책 자체의 점수를 올리는 보정이나 원점수와 동일한 표본 통계 |
| 예상 최종 점수 예측기 | 해당 정책을 따를 때의 결과를 추정하는 화면 기능 | 행동 선택용 가치망의 출력과 동일한 모델 |

대표 성능에는 정책·평가 게임 수·평가 시드 집합·원점수/보정 여부·비교 상대를 함께 둡니다. 서로 독립적인 시드 집합의 평균 차이는 독립 비교로 분석합니다. 모델 선택창의 반올림 대표값과 보고서의 표본 평균을 비교할 때도 이 조건을 확인해야 합니다.

### 대응 평가와 불확실성

**대응(paired) 평가**는 같은 게임 조건에 대응시킨 두 정책의 점수 차이를 분석합니다. 단, 두 정책이 다른 행동을 하면 난수 소비도 달라질 수 있습니다. 따라서 같은 seed를 사용했어도 공통 난수(CRN)의 실제 결합 방식과 대응 차이의 분산을 확인해야 합니다.

**95% 신뢰구간(CI)**은 해당 평가의 추정 불확실성입니다. 차이의 구간이 0을 포함하면 그 평가만으로 우위를 확인하지 못한 것입니다. 동등성이나 비열등성을 입증하려면 각각의 사전 기준이 필요합니다. 비열등성은 미리 정한 허용 손실을 기준으로 판단합니다.

제어변량 보정은 게임 중 각 결정 뒤의 운을 측정해 뺍니다. 이때 정확한 전이 기대값을 사용합니다. 그래서 운 측정기로 어떤 고정된 가치 함수를 써도 보정 항의 평균은 0이며, 비교하는 정책마다 측정기가 달라도 차이 추정은 편향되지 않습니다. 측정기가 정책의 실제 가치를 잘 맞출수록 분산만 줄어듭니다. LYRA 후속 평가에서는 평가 대상 가치망 자신과 Hinge 가치표를 측정기로 씁니다. 계수는 개발 평가에서 정한 뒤 봉인 평가에 고정했습니다. 10K쌍 봉인 평가에서 대응 차이의 게임당 표준편차는 원점수 약 195점, 보정 후 약 18.6점이었습니다. 같은 정밀도에 필요한 게임 수가 약 1/110입니다. 같은 시드 대응만으로는 원점수 분산이 거의 줄지 않았습니다. [출처 L6](sources.md#lyra-연구와-후속-방향)

반복 상태와 행동별 rollout 수를 독립 게임 수로 세지 않습니다. 궤적에서 뽑은 여러 상태의 불확실성은 가능하면 게임 단위로 묶어 계산합니다. 내부 rollout이 수십억 회여도 독립 게임·상태 수는 별도로 계산합니다.

### 선택과 확인을 분리

- 개발 선별의 최고 평균을 최종 성능으로 쓰지 않습니다.
- 모델·정책·표본 수를 고정한 독립 확인 결과를 우선합니다.
- 같은 게임을 학습·선택·최종 확인에 재사용했다면 그 범위를 밝힙니다.
- 미완료 평가의 완료 구간, 재사용한 holdout, 후속 정정이 있는 자료는 그 상태를 표시합니다.
- 실제 수행한 평가와 README의 계획·실행 명령을 구분합니다.

## 정확성의 범위

VELA의 가치표는 보조 문제를 바탕으로 계산했습니다. IID 보조 문제는 미래 카드를 전체 덱에서 복원 추출하는 것으로 완화하고, 온라인 정책에서는 실제 잔여 덱으로 전개할 수 있습니다. 손패 완전 열거·정확 확률 합산·특정 종반 해결 중 무엇을 보장하는지 구분합니다.

정확한 실제 덱 솔버도 시간·노드 한도로 미해결 상태가 생길 수 있습니다. 이런 결과는 **UNKNOWN(미해결)**으로 남기며 손해 0이나 계산 불가능의 증거로 처리하지 않습니다. 표본의 행동 일치, 전체 가치 오차 보장, 전역 최적성도 구분해야 합니다.

컴파일러·정밀도 변경 뒤 가치·행동 일치를 확인한 표본 결과는 중요하지만 전 상태의 수학적 동등성으로 확대하지 않습니다. 특히 작은 행동 차이에서 FP16/BF16·연산 순서가 판단을 바꿀 수 있습니다.

## 실행 비용의 기준

다운로드 파일 크기, 압축 해제한 가중치 크기, WASM heap, 브라우저 RAM, GPU 메모리를 구분해 보고합니다. 원본 가치표의 배포 필요 여부는 각 실행 모델의 의존성을 확인해야 합니다.

속도는 동일 상태 분포·같은 정책·같은 실행 환경에서 비교합니다. 단일 선택기의 microbenchmark, 연구 GPU 처리량, 전체 root 판단 지연, 게임당 wall time을 같은 배율로 바꾸지 않습니다. 더 깊은 탐색이나 가지치기로 행동이 달라지면 구현 가속과 정책 변경을 분리합니다.

## 용어

- **가치 추정:** 현재 상태에서 앞으로의 결과를 수치로 추정하는 것. 구체적인 출력이 총점인지 잔여 이득인지는 모델의 출력 정의를 확인합니다.
- **기대값 탐색(expectimax):** 확률 결과는 평균하고 관측 후 행동은 선택하는 탐색.
- **1-step / 2-step:** 해당 planner가 한 번 또는 두 번의 행동·결과를 내다보는 깊이. 모든 무료 연쇄·종료 처리까지 동일 구현이라는 뜻은 아닙니다.
- **지평(horizon):** 가치 계산이 다루는 남은 유료 주사위의 범위. 실제 행동 수와 다릅니다.
- **교사·증류:** 비싼 모델이나 탐색의 판단을 저렴한 모델이 배우도록 만드는 방식.
- **backup:** 다음 상태의 추정값을 게임 규칙과 확률로 합쳐 현재 학습 정답을 만드는 계산.
- **on-policy / 방문 분포:** 실제 해당 정책이 플레이하며 만나는 상태들의 분포.
- **희소 보정(override):** 기존 선택을 대부분 유지하며 일부 상태에서만 바꾸는 방식.
- **결정 churn:** 재학습 후 잘못된 선택의 개선과 기존 좋은 선택의 손상이 함께 생기는 현상.
- **CV:** 이 연구의 운 보정 문맥에서는 control variate(제어변량). 일반적인 cross-validation(교차 검증)과 구분합니다.
