# LYRA v2 — 실행·연결

LYRA v2는 M₄₀ 가치망(384차원, 8층, 헤드 8)과 모든 합법 효과 클래스에 대한 FP32 1-step expectimax를 사용한다. 실제 비복원 덱, 종료 자식의 실제 점수, 효과 클래스 오름차순 동률 처리를 유지한다. 손패의 물리 카드 ID를 입력하고 결과를 입력 손패 슬롯으로 돌려준다. 학습·변환 방법은 [재현 가이드](../../../research/reproduction/README.ko.md#lyra-v2--m₄₀-신경망-가치-모델), 평가 근거는 [연구 보고서](../../../research/lyra-v2/report-ko.md)에 있다.

## 모델 준비와 실행

화면 흐름은 모델 선택 → 실행 장치·사용량·탐색 깊이 선택 → 모델 준비 → 시작/적용이다. VELA의 준비 컴포넌트와 X36의 실행 장치 선택 UI를 공유한다. 기본 모델은 VELA이며 LYRA의 실행 장치·사용량·탐색 깊이는 접속 간 저장하지 않는다.

기본 탐색은 1-step, 깊은 탐색은 같은 가치망으로 두 행동 뒤까지 전개하는 2-step expectimax다. 기본값은 1-step이다. 높음과 깊은 탐색을 함께 선택하면 진행 전에 메모리 사용 경고를 표시하며, 사용자가 계속 진행할 수 있다.

- 패키지: `public/models/lyra-v2/lyra-v2.bin.gz`, **67,737,222 bytes**. 모델·특징·CPU/GPU WASM·`LICENSES.txt`의 5개 파일을 포함한다.
- localhost·루프백에서는 프로젝트 파일을 읽고, 일반 호스팅에서는 `https://adventure.alfm201.workers.dev/models/lyra-v2/lyra-v2.bin.gz`를 요청한다. 원격 배포 전 R2 객체와 Worker 허용 경로·크기를 별도로 갱신해야 한다.
- `model.js`는 원본 체크포인트·ONNX·특징·메타데이터·패키지 해시를 고정한다. 전체 패키지, 압축 해제 결과와 내부 파일을 검증한다. 입력 폭은 검증된 메타데이터의 384차원을 사용한다.
- 브라우저 저장에 동의하면 압축 패키지를 Cache Storage에 보관한다. 새 패키지를 검증하고 저장한 뒤 같은 캐시의 이전 패키지를 정리한다. 저장 실패는 현재 접속의 사용을 막지 않는다. localhost에서는 저장 선택을 표시하지 않는다.
- 같은 접속의 CPU/GPU 전환은 메모리의 압축 패키지를 재사용하며 추가로 다운로드하지 않는다. 실행 장치가 같고 사용량이나 탐색 깊이만 바뀌면 Worker·ORT 세션도 재사용한다. 준비 단계에서는 변경을 예약하고 적용 때 반영하므로 취소하면 기존 설정을 유지한다.

CPU는 ONNX Runtime Web 1.30.0의 WASM 1스레드를 사용한다. GPU는 하드웨어 WebGPU 어댑터와 `ort.all.min.mjs`/JSEP WASM 조합을 사용한다. 별도 WASM 요청 없이 검증된 바이너리를 전달한다. 자동은 GPU 준비·추론 실패 시 CPU로 전환하고, GPU 직접 선택은 실패를 보고한다.

사용량에 따른 배치와 양보 시간은 다음과 같다. 모든 후보와 전이를 계산하며 정밀도는 동일하다.

| 사용량 | CPU | GPU |
|---|---|---|
| 낮음 | 최대 8개, 배치 사이 16ms 양보 | 최대 16개, 8ms 양보 |
| 보통 | 최대 64개, 배치 사이 타이머 양보 | 최대 64개, 배치 사이 타이머 양보 |
| 높음 | 전체 후보 한 배치 | 전체 후보 한 배치 |

압축 해제 컨테이너와 불필요한 로딩 복사본은 엔진 초기화 전에 정리한다. 자동 GPU는 CPU 전환에 필요한 가중치를 유지한다. GPU 계산 중 버퍼 재사용은 유지하고 완료 후 미사용 캐시만 정리한다. [런타임 캐시 안내](../../../public/runtime/onnxruntime-web/1.30.0/LYRA-CACHE.md) 참고.

낮음·보통은 입력 특징도 배치별로 생성한다. 취소 요청은 계산 대기열과 별도로 받아 배치 사이와 깊은 탐색의 상태 전개 중에 확인한다. 실행 중인 단일 추론은 완료를 기다린다. 취소된 계산의 남은 배치는 생략하며, 모델과 세션을 유지해 다음 요청을 처리한다.

## 예상 최종 점수와 진단

`public/models/lyra-v2/predictor.json`은 M₄₀ FP32 1-step 최선 Q와 상태 특징 50개를 입력받는 전용 예측기다. 자기망 CV 라벨로 학습한 보정표와 300개 트리를 사용하며 행동 선택에 관여하지 않는다. 게임 종료 시에는 실제 점수를 반환한다.

깊은 탐색에서는 2-step 최선 Q에 같은 보정 모델을 적용한다. 이 조합의 최종 점수 예측 정확도는 미검증이며, 탐색 깊이 옆 툴팁에서 안내한다. 아래 연구 평가와 예측기 초기값은 기본 탐색 기준이다.

직렬화 형식 `lyra-v1-score-v1`은 v1과 공유하지만 진단 ID는 `lyra-v2-score-v1`이다. 체크포인트·ONNX·패키지 해시와 카드 클래스 배열까지 맞아야 사용한다. 예측기 로딩 실패 시 추천은 유지하고 예상 점수만 생략한다.

모델 선택창은 FP32 확인 평가의 결합 CV 평균 1880.09를 반올림한 **연구 평가 약 1,880점**을 표시한다. 예측기의 초기값은 학습·검증 9,000판의 자기망 CV 라벨 평균인 **1879.85점**이다. 시험 1,000판은 이 보정에서 제외됐으며, 그 라벨 평균은 1879.83점이다. 서로 다른 추정량과 표본으로 구한 값이므로 강제로 일치시키지 않는다.

진단 정보에는 `lyra-v2`, 원본 체크포인트 해시, `M₄₀`, 실제 탐색 깊이, FP32, 선호·실제 실행 장치, CPU 전환 사유, 예측기 상태와 ORT 버전을 기록한다. 깊은 탐색 결과의 정책 ID는 `lyra-v2-depth2`로 구분한다.

## 검증

테스트 서버 실행 후 `node tests/models/lyra-v2-artifacts.mjs`, `node tests/models/lyra-v2.mjs`, `node tests/models/lyra-v2-download.mjs --hosted`, `node tests/ui/lyra-v2.mjs`로 검사한다. 원본 PyTorch와의 비교 기준은 표본에서 Q 절대 오차 0.002점 이하, 추천 클래스 불일치 0이다. 모든 가능한 상태의 비트 동일성이나 행동 동일성을 증명하는 검사는 아니다.

탐색 깊이와 취소 처리는 `node tests/models/lyra-depth.mjs`, `node tests/models/lyra-depth-browser.mjs`, `node tests/ui/lyra-depth.mjs`로 확인한다. 독립 expectimax 계산, 기본 탐색 회귀, 실제 CPU/GPU 추론, 배치 취소, 설정 전환과 다국어 화면을 검사한다.

변환·참조값 생성·메모리 측정 자료는 `temp/lyra-v2-integration/`, 회귀 결과는 `tests/results/lyra-v2*.json`에 보관한다. 메모리 안내는 별도 Chrome PID의 RAM·VRAM 준비/추론/전환 피크에 여유를 더해 정한다. 기기별 최소 요구량이나 모든 상태의 절대 피크를 뜻하지 않는다.
