# 이미지 캐시

`public/assets/*.png`의 SHA-256과 크기는 `image-manifest.js`에 자동 생성됩니다. 페이지 버전은 캐시 키에 포함하지 않습니다. 이미지가 같으면 페이지 소스만 배포해도 저장된 이미지를 재사용합니다.

- `node scripts/serve.mjs` 또는 `npm start`: 서버 시작 전에 목록 자동 생성. 실행 중 이미지를 교체했다면 서버를 다시 시작하거나 `npm run assets:generate`를 실행합니다.
- `npm run assets:generate`: 파일 내용으로 목록 생성. 내용이 같으면 파일을 다시 쓰지 않습니다.
- `npm run assets:check`: 실제 이미지와 목록이 다르면 실패. GitHub Actions에서도 push/PR마다 실행합니다. 이미지를 변경한 커밋에는 생성된 목록을 함께 포함해야 합니다. 일반 페이지 패치에서는 갱신 작업이 없습니다.

캐시는 앱 경로별 `adventure-images-v1:` 이름을 사용합니다. `v1`은 저장 형식이며 배포할 때마다 올리지 않습니다. 이미지별 콘텐츠 해시로 읽고, 크기와 해시를 검증합니다. 없는 항목만 서버에서 받아 검증 후 저장합니다. 다운로드 시 해시 쿼리와 HTTP 재검증을 사용하므로 같은 파일명의 이전 HTTP 캐시를 무조건 신뢰하지 않습니다.

저장소 차단·용량 초과 시에도 내려받은 이미지로 표시합니다. 사용자가 사이트 데이터를 삭제하거나 브라우저가 캐시를 회수하면 필요한 이미지를 다시 받습니다. 영구 저장 권한은 요청하지 않습니다. Service Worker를 등록하지 않으므로 페이지 코드의 업데이트 방식에는 영향을 주지 않습니다.

현재 목록에 없는 항목은 저장 후 7일이 지난 경우 다음 새 페이지 로딩에서 정리합니다. 다른 탭과 롤백을 위해 최근 교체된 항목은 잠시 남깁니다. 음성 등 다른 캐시는 정리하지 않습니다. Blob URL은 이미지 로더 해제 시 반환합니다.

로컬과 배포 파일의 불일치 또는 전송 손상은 해시 불일치로 처리하고 기존 이미지 로더의 재시도·실패 표시를 사용합니다. 캐시 실패가 전체 페이지 실행을 막지 않도록 저장소 작업은 선택적으로 처리합니다.
